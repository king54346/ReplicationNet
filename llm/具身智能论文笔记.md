### DeepMimic ⭐

**DeepMimic: Example-Guided Deep Reinforcement Learning of Physics-Based Character**

🔗 <https://xbpeng.github.io/projects/DeepMimic/index.html>

> 2018 年开创性工作，让动画和游戏人物完成强化学习驱动的动作。

**核心要点：**

1. **单段动捕 → 单个动作**：仅需一段动捕数据作为参考动作，训练 RL 算法完成跑步、后空翻、侧手翻等动作。
2. **加速训练**：通过 RSI（直接在空翻高能时刻初始化）和 ET（一旦失败就马上重开），让训练尽可能处于高奖励、高反馈区。
3. **动作 + 任务**：加入额外的任务观测值和任务奖励函数，实现既模仿动作又完成任务（旋踢指定区域、扔球到指定区域、走平衡木、越障）。
4. **多段动捕 → 多动作切换**：用多段不同动作的动捕数据训练同一个 RL 算法，通过指令切换不同动作（向不同方向行走 / 空翻）。

### OmniRetarget ⭐

**OmniRetarget: Interaction-Preserving Data Generation for Humanoid Whole-Body Loco-Manipulation and Scene Interaction**

🔗 <https://omniretarget.github.io>

> 亚马逊发布，提供了一套 Motion Tracking 的**最佳实践**。宇树机器人春晚蹬墙后空翻、翻越障碍物，都可以用这套工作流实现。

#### 交互网格

1. 人类穿戴动作捕捉设备采集数据。
2. 通过**德劳内四面体化**，生成人类和物体的三维交互网格。
3. 网格可以想象成：关键接触点和关节作为**点**，橡皮筋组成**边**。
4. 目标：让机器人的网格尽可能接近人类的网格（橡皮筋不能拉扯过度）。
5. **拉普拉斯变形能量越低越好** → 实现人类动捕数据到机器人轨迹的重定位。

#### 数据增强

> 只用 **一条** 人类动捕数据，就能举一反三生成无数条类似的机器人轨迹数据——就像孙悟空拔出一根毛，变出一群猴。

- 把箱子放大、把平台加高、把物体挪位置……每次微小改动后，重新求解交互网格的拉普拉斯变形能最小化。
- 每条轨迹既符合物理规则，也保留交互逻辑：身体不穿模、四肢不打架、脚底不打滑、动作不突兀、关节不脱臼。
- 巧妙解决了高质量数据昂贵稀少的问题。
- 最终用这些轨迹训练 RL 算法，再 **Sim2Real** 部署到真实机器人。

### HumanX ⭐

**HumanX: Toward Agile and Generalizable Humanoid Interaction Skills from Human Videos**

🔗 <https://wyhuai.github.io/human-x>

> 让宇树 G1 机器人与真实物体交互：接抛篮球、三步上篮、投篮防守、踢足球、拳击格挡、搬桶装水。

包含四部分：**XGen** → **XMimic** → **知识蒸馏** → **部署推理**

#### XGen — 生成训练数据

1. 从人类视频中提取 3D 人体姿态和轨迹。
2. 基于 GMR 重定向算法，把人类关键点映射对齐到机器人身上，生成机器人动作序列。
3. **第一条轨迹（反向仿真）**：从接到球的一瞬间开始让时间倒流，用物理引擎反向仿真，得到球从天上飞过来、必然能被手接住的完美轨迹（先射箭再画靶 🎯）。
4. **第二条轨迹（接触仿真）**：球飞到手里后，对准双掌中点，保证力闭合且不穿模干涉。
5. **第三条轨迹（正向仿真）**：松手后，正向仿真让球自然下落或滚动。
6. **轨迹拼接**：使拼接点位置、速度连续且符合物理。
7. **数据增强**：用一段人类视频生成数百种不同场景的交互训练数据。
8. **输出数据**：机器人每帧的动作 + 物体每帧的速度和角速度 + 每帧是否接触。

#### XMimic — 训练交互技能

1. 用 XGen 生成的数据，每个技能单独训练一个 **Teacher** 专精模型。
2. 多个技能 → 多个 Teacher 模型。
3. 将所有 Teacher 模型**知识蒸馏**，浓缩整合到一个 **Student** 模型中。
4. **无需设计任何奖励函数**（无奖励模仿学习）。

#### 最终推理 — Student 模型

动捕获得物体位置（篮球上贴反光标），即可实现机器人与物体交互。

#### 蒸馏成 Student 模型的意义

| 优势 | 说明 |
|------|------|
| **无需参考动作，更像本能直觉** | Teacher = 看着乐谱弹琴的人；Student = 听到音乐就能即兴弹的人。当人上下晃篮球、挥舞拳击时，机器人做出**本能直觉反应**（马尔科夫性：没有记忆，只凭当下做出动作）。 |
| **一个模型兼容所有技能** | 不需要遥控器手动切换技能——机器人看到篮球就接篮球，看到箱子就搬。 |

### HoST — 多姿势站立

**HoST: Learning Humanoid Standing-up Control across Diverse Postures**

🔗 <https://taohuang13.github.io/humanoid-standingup.github.io>

> 让机器人从各种姿势（趴在地上、靠在墙上、坐在椅子上）自主站起来。

**关键设计：**
- 将站起过程分为 **翻身 → 跪起 → 站立** 三个阶段，每个阶段用不同的奖励函数引导。
- 训练初期施加向上的「拉力」帮助从平躺翻到跪姿，随训练进展逐渐减少拉力。
- 采用**课程学习**（模拟婴儿学步）加速初期探索。
